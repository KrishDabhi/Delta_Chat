# Intelligent Unified Report (Document Delta & Grounded Chat)

A production-ready FastAPI microservice that ingests engineering and architectural document revisions, computes a deterministic structural delta (Added, Removed, Modified, Moved), and exposes a strictly-grounded RAG chatbot to query the changes.

---

## 💡 What Is This Project?

Unlike standard document comparison tools that rely on fragile pixel-diffing or hallucination-prone LLM Vision models, this system standardizes documents into a **Canonical Representation** before computing the delta deterministically using spatial indexing and bipartite matching. 

Supported ingestion formats:
1. **Native PDF**: Born-digital PDFs using dictionary extraction.
2. **Scanned PDF**: Raster images using OpenCV + Tesseract (OCR) and RANSAC (deterministic geometry extraction).
3. **DWG**: Structurally stubbed for scope, wired directly into the canonicalizer.

Once the delta is computed, a **Grounded RAG Chatbot** allows users to ask questions about the changes. The chatbot is strictly constrained by a system prompt that mandates exact citations in the format `[Source: Delta Report | Page N | Region]` and refuses to answer questions outside the scope of the provided documents.

## 🚀 Getting Started

### 1. Requirements

- Python 3.12+
- Tesseract OCR (must be installed on your system and path configured)

### 2. Setup Environment

Create a virtual environment and install the pinned dependencies:

```bash
python -m venv .delta_chat
# Windows:
.\.delta_chat\Scripts\Activate.ps1
# Mac/Linux:
source .delta_chat/bin/activate

pip install -r requirements.txt
```

### 3. Configuration

Copy the example environment file and populate it with your API keys:

```bash
cp .env.example .env
```

You will need:
- `GROQ_API_KEY`: For the LLM inference (Llama-3.3-70b is used for chat).
- `PINECONE_API_KEY`: For the vector store index.
- Ensure `TESSERACT_CMD` matches your system's Tesseract installation path.

### 4. Start the Server

Start the FastAPI backend using `uvicorn`:

```bash
uvicorn src.main:app --reload --port 8000
```

The interactive API documentation (Swagger) will be available at: **http://localhost:8000/docs**

## 📖 API Guide & Usage

The pipeline is entirely asynchronous. Heavy ingestion tasks (like OpenCV RANSAC) are offloaded to a ProcessPoolExecutor to ensure the web server event loop is never blocked.

### 1. Ingest Documents (Trigger the Pipeline)

Upload the base revision (Rev A) and the modified revision (Rev B) to trigger the comparison pipeline.

```bash
curl -X POST "http://localhost:8000/api/v1/delta/ingest" \
     -H "Content-Type: application/json" \
     -d '{
           "job_label": "Sample Revision Comparison",
           "pid_a_path": "data/samples/sample_01_rev_a.pdf",
           "pid_b_path": "data/samples/sample_01_rev_b.pdf"
         }'
```

*Returns a `job_id` instantly while processing in the background.*

### 2. Check Job Status

Poll the job status using the `job_id` returned from the ingest endpoint:

```bash
curl -X GET "http://localhost:8000/api/v1/delta/{job_id}/status"
```

*Wait until the status is `"complete"`.*

### 3. View the HTML Delta Report

Once complete, the system generates a human-readable visual HTML report grouped by page and change type (with color-coded badges and confidence scores).

```bash
curl -X GET "http://localhost:8000/api/v1/delta/{job_id}/report/html"
```

### 4. Query the Grounded Chatbot (RAG)

Ask questions about the changes. The LLM will use Pinecone to retrieve the exact natural-language RAG chunks generated by the Delta Engine.

```bash
curl -X POST "http://localhost:8000/api/v1/chat" \
     -H "Content-Type: application/json" \
     -d '{
           "job_id": "{job_id}",
           "query": "What changed on page 1?"
         }'
```

**Example Structured Response:**
```json
{
  "answer": "On page 1, the text 'Valve V-201' was added to the document in the top-right region [Source: Delta Report | Page 1 | top-right]. Additionally, the dimension '150mm' was removed from the center region [Source: Delta Report | Page 1 | center].",
  "citations": [
    "[Source: Delta Report | Page 1 | top-right]",
    "[Source: Delta Report | Page 1 | center]"
  ],
  "retrieval_chunk_count": 8
}
```

## 🏗️ Architectural Decisions (No "Vague Shit")

The system abandons generative LLMs (Vision Models) during the ingestion and comparison phase to completely eliminate hallucinations.

1. **Deterministic Geometry Extraction**: Scanned PDFs use OpenCV Canny edge detection fed into a scikit-learn RANSAC regressor. This iteratively fits clean mathematical line segments through noisy pixel data, turning a messy scan into a clean list of vectors.
2. **Spatial Bipartite Matching**: To match Rev A elements to Rev B elements, we load Rev B into a Shapely `STRtree` spatial index for `O(log N)` spatial lookup. We then build a cost matrix (`1 - (0.6 * IoU + 0.4 * Text Similarity)`) and run the Hungarian algorithm (SciPy `linear_sum_assignment`) to guarantee a mathematically optimal 1:1 pairing.
3. **5-Rule Classifier**: A rigid heuristic classifies changes as `ADDED`, `REMOVED`, `MODIFIED`, or `MOVED` based strictly on coordinate IoU thresholds and SHA-256 content hashes.
4. **Strictly Grounded LLM**: The LLM (Groq) is used *only* at the very end to provide a conversational interface. The system prompt injects strict constraints prohibiting information outside the provided Pinecone context and strictly enforcing inline citation formatting.
5. **Observability Built-In**: Every stage is decorated with `@trace_stage` (using `structlog`), appending structured JSON telemetry with correlation IDs and tracking LLM token costs.

## 🧪 Evaluation Harness

The repository includes a deterministic evaluation harness to verify Delta Engine accuracy (Precision/Recall/F1) and Chatbot grounding (Keyword Coverage) without relying on an "LLM-as-a-judge".

### Option A: via API
You can programmatically trigger the evaluation and receive a structured JSON report containing metrics for all pairs and any failure cases:

```bash
curl -X POST "http://localhost:8000/api/v1/eval"
```

### Option B: via CLI
To run the scorecard eval locally against labeled ground-truth datasets and print the scorecard:

```bash
python eval/run_eval.py
```
